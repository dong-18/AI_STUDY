      - 公司电脑统一使用什么处理器？

  context 提到了电脑

  问题询问的具体属性是否在 context 中？
          ├─ 有：依据条款回答
          └─ 没有：明确拒答
  4. 在验证集增加 10～20 条类似边界题，但不要复制训练集或测试集原问题。用扩充后的验证集选择 checkpoint。
  5. 重新训练后，先看：
      - 验证集拒答准确率
      - 可回答题错误拒答率
      - 关键词召回率
接下来的做法：
  1. 使用更新后的 train.jsonl 重新训练。
  2. 用扩充后的 val.jsonl 比较各 checkpoint。
  3. 同时观察拒答准确率和错误拒答率，不能只看拒答准确率。
  4. 将当前 test.jsonl 作为诊断集继续查错。
  5. 最后重新制作一份从未运行、未查看答案的新测试集，用它报告最终成绩。

 四，增加拒绝回答的例子后，发现有过度拒答，错误拒答率：百分之0.几，主要在对复合问题（一个句子问两个属性）判断过于保守
 解决：在训练集增加约 10～15 条“可回答复合问题”

 五，为什么在没有添加拒绝答的样本的时候，这个例子可以很好的泛化成功回答呢
• 因为添加拒答样本前，模型的默认策略更接近：

  > 只要问题和 context 有关，就尽量从 context 中提取内容回答。

  这种策略虽然容易编造，但对“全勤奖金额 + 条件”这类复合问题很有效，因为相关信息都在 context 中，模型直接复述就能答对。

  加入大量拒答样本后，模型的决策边界发生了变化：

  > 不仅要相关，还要判断问题询问的每个属性是否明确存在；稍微不确定就拒答。

  对于 0.5B 小模型，这种边界很难学得精确，容易从“过度回答”摆向“过度拒答”。

  具体原因主要有四个。

  1. 拒答话术过于统一

  大量负样本都使用类似答案：

  > 抱歉呀，现有制度资料中没有找到相关规定……

  这句话非常固定，模型很容易学习。相比之下，正常答案内容各不相同，学习难度更高。因此当模型不确定时，输出固定拒答话术能更容易降低训练损失。

  2. 负样本的问题形式产生了误导

  新增的困难负样本经常使用：

  - 多少
  - 哪个
  - 哪一种
  - 几个工作日
  - 什么型号
  - 哪家供应商

  而错误拒答的问题是：

  > 年终全勤奖有多少钱，需要满足哪些条件？

  3. 复合正例覆盖不足

  训练集中虽然存在少数复合问题，但形式不够丰富。模型没有充分见过：

  > A是多少，B需要满足什么条件？

  所以它可能把“一个句子问两个属性”理解成高风险问题。只要不能立即确认两个部分，就使用学得非常熟练的拒答模板。

  4. 原来的成功不一定代表真正学会了边界

  未添加拒答数据时，它回答正确，可能只是因为模型习惯复述 context，而不是已经掌握了：

  > 逐项检查问题中的信息是否都能由 context 支持。

  这种“积极回答”策略在可回答题上表现不错，但在制度未规定的问题上容易编造。加入拒答样本后，原来隐藏的问题才表现为过度拒答。
